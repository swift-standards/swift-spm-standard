# swift-spm-standard

Use this package when you need SwiftPM's own data as values: a manifest as `swift package dump-package` prints it, the managed dependencies in SwiftPM's workspace state, or the dependency declarations written in a `Package.swift`, read as text without a toolchain. Start from `Package.Manifest.Evaluation` to decode dump-package output faithfully, including traits, trait conditions and local source-control locations. Use `Package.Manifest` only when you also need to encode a manifest. Use `Package.Resolution` for workspace state, `Package.Dependency.Declaration.Parser` for declarations in manifest text, and `Package.Manifest.recognizes(_:)` to tell a manifest from another file named `Package.swift`. To run SwiftPM and get these values, use swift-package-manager. For dependency graphs across a workspace, use swift-package-graph. For package, product and target names alone, use swift-package.

## Laws

- Dump-package keys that are not modelled are ignored on decode. Unknown platform names, target types or library link kinds, and a tools version or semantic version with trailing text, fail the decode.
- Decoding fills a dependency's products from the targets' `.product(name:package:)` edges whose package matches the dependency's name (for `Package.Manifest`) or identity (for `Package.Manifest.Evaluation`). The order is the order of first appearance across targets, without duplicates. A dependency that no target references keeps an empty list. Encoding never writes a dependency's products, so after a round trip they are exactly what the target edges give.
- `Package.Manifest.Evaluation` is strict. A dependency record needs exactly one of `fileSystem`, `sourceControl` and `registry`, holding exactly one record with a non-empty identity. A source-control location needs exactly one `remote` or `local` entry: a non-empty, valid URI or a non-empty path. A local location stays a path, and no URI is invented for it. `Package.Manifest` is lenient: it takes the first record of each array and cannot decode a local source-control location.
- A registry identity is split at its first `.` into scope and name, and an identity with no `.` fails. A registry dependency's evaluated identity is `scope.name`. When `Package.Manifest` encodes a registry dependency, it writes that identity in place of the dependency's name, so a different name does not survive a round trip.
- On the dump-package wire, every version requirement except exact, branch and revision is a range with an inclusive lower bound and an exclusive upper bound. `from` and `upToNextMajor` encode as `[v, (major+1).0.0)` and `upToNextMinor` as `[v, major.(minor+1).0)`, and all of them decode as `Package.Requirement.range`. A bound's inclusivity is not written. `Package.Requirement`'s own coding keeps every case and both inclusivity flags, and it refuses to encode an unbounded bound.
- A target dependency's condition is kept in `Package.Manifest.Target.conditions` only when dump-package gives one. A product dependency's module aliases are read and discarded, and they encode as `null`. A `SupportedPlatform` drops its options and encodes them as an empty list.
- `Package.Resolution` decodes only schema version `Package.Resolution.supportedVersion`, and refuses every other version. It ignores artifacts and prebuilts. It models the dependency states `sourceControlCheckout`, `fileSystem` and `edited`, and refuses every other state and every unknown `Package.Resolution.Reference.Kind`.
- A checkout carries exactly one of a branch and a version. A branch that looks like a version stays a branch. Only an `edited` dependency may carry `basedOn`, and what it supersedes must be a source-control checkout. `Package.Resolution.Dependency.revision` exists only for a checkout, so an edited dependency reports none, even though the checkout it supersedes has one. A reference's kind does not determine its state. `Package.Resolution.dependency(for:)` returns the first dependency with that identity.
- `Package.Dependency.Declaration.Parser` finds every package dependency call anywhere in the text, in source order, and skips line comments, nested block comments and string contents. Within one call, `url:` takes precedence over `path:`, which takes precedence over `id:`, and only top-level labels count. The argument must be a single string literal without interpolation. Raw and multiline literals are accepted, and escapes are decoded only in non-raw literals. Any other argument, a missing argument or an unclosed call becomes `Package.Dependency.Declaration.malformed` in the result instead of a thrown error. Only invalid UTF-8, an unterminated string literal or an unterminated block comment throws. A declaration's line is the line of the call's opening parenthesis.
- `Package.Manifest.recognizes(_:)` returns `false` for text that the parser cannot tokenize.
